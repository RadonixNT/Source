Running and Monitoring a Program

Bring the prepared job into motion deliberately, understand what the machine may do before the first cut, and use the screen and the actual machine together to follow the operation.

Expanded draft for review. This chapter describes the reviewed application behavior. The approved job sheet, machine builder's operating instructions and the actual equipment configuration determine the permitted cutting conditions and access procedure.

16.1 Understand what Run actually starts

Think of a simple routed panel. The file describes where the cutter must travel, but the machine may still have to collect the correct cutter, apply its stored compensation and reach the job's entry position. These actions are part of getting the program under way. The first movement after Run is therefore not necessarily the first visible cutting line in the preview.

A request, an accepted request and a finished operation are different

When you press Run, the application checks whether it can admit the operation and checks the required tool state. It then asks the appropriate machine operation to proceed. An accepted request tells you that the start or preparation has been admitted. It does not tell you that preparation has finished, that material is being cut, or that all later actions will succeed.

Table 16-1. Three questions to keep separate
QuestionWhat answers itWhat to do next
Was my start request accepted?The operation report and any warning returned by the application.Observe the preparation or execution that follows.
What is the machine doing now?Motion, tool and equipment indications, the program display and the physical operation seen from the operating position.Check that this stage agrees with the approved sequence.
Has the job finished?The recorded termination reason, any following parking motion and the actual machine condition.Complete the end-of-job checks before access or unloading.

Your role while the program runs

You do not need to understand the program as a software developer. You do need to recognize the intended cutter, the starting area, the expected first movement, the approximate cutting sequence and the normal behavior of the equipment. If you cannot say where the head is expected to go next at the start, return to the setup and preview review before pressing Run.

Screen information and physical observation answer different questions. A changing position display shows commanded movement information. A changing source line shows reported program progress. Neither proves that the stock remains fixed or that the cutter is producing an acceptable edge. Observe those conditions from the designated operating position and follow the machine's procedure if anything becomes abnormal.

This chapter covers an ordinary prepared job and the observations needed throughout it. Chapter 17 deals with interruption and recovery in more detail. Chapter 18 deals with deliberately beginning partway through a file. Use those procedures when the job is no longer an ordinary first start.

16.2 Complete the pre-run check at the machine

A pre-run check joins the information on the screen to the real setup. It is not enough to see an available Run button. The software can check connection, homing and certain machine conditions, but it cannot recognize a wrongly placed clamp from the preview or decide whether you loaded the correct production revision.

Use the approved job sheet as your reference. This should identify the part, material, program revision, work origin, tools and operating conditions. If the shop uses a first-piece approval process, establish who must approve that first result and when. Do this before starting, while there is time to resolve a mismatch without leaving a partly machined workpiece.

Check the job, then the setup, then the controls

Homing and work-origin setting are separate. Homing establishes the machine's reference; the work origin relates the job to the stock. A machine can be fully homed and still cut in the wrong place if the work origin is wrong. Likewise, a correct-looking preview does not prove that the physical stock lies under that path.

Include the whole route, not just the cutting shape

Review the intended start state after any interruption or change of operator. Ask what has changed since the last checked setup: a cutter, work reference, stock position, loaded file or selected start line. A previous successful run is useful evidence only when the relevant setup remains the same. Do not use the last operator's open screen as a substitute for identifying the current job.

Example: the file is correct but the setup is not

The preview shows the expected panel, but the stock has been placed against another locating edge. Starting the correct file would still place the cuts incorrectly. Stop the preparation process, establish the intended datum and verify the work origin. Editing the program or shifting the preview is not the ordinary correction for an incorrectly prepared setup.

Finish by placing yourself at the designated operating position with a clear view of the initial operation and access to the controls required by the machine's operating procedure. All people involved should understand that the next Run request can initiate motion. The result of this check should be a specific expectation about the first operation, not simply a general impression that the machine looks ready.

16.3 Know where the next Run is intended to begin

The visible file has a beginning, but the next Run request does not always mean “start at the first line.” The application distinguishes an initial start, continuation of retained progress and an explicitly selected source line. Understand which of these applies before you press Run, particularly after a pause, stop or review of the source text.

For an ordinary new program with no explicit start selection, the application starts from its normal initial state. The setting named StartFromNextCuttingLine influences a fresh or explicitly selected entry. When enabled, it searches forward for an accepted cutting entry and prepares the required starting state. Consequently, the line at which machining begins can be later than the first line or the line originally requested.

Inspection selection does not establish start intent

A single click in the source view selects text for inspection. The viewer can also follow reported execution. Neither is a reliable instruction to restart at that line. In contrast, confirming the start-line dialog, or double-clicking a source line when the application permits it, records an explicit start request. Selecting a start line does not itself move the machine; a subsequent Run is still required.

Earlier rows can appear completed when you deliberately select a later start. This is a visual representation of the planned entry. It is not evidence that those earlier cuts were made in the present workpiece. If another person prepared the screen, establish whether its appearance comes from actual execution or from start selection.

Why ordinary continuation is different

A pause can occur partway along a long movement. The controller retains more information than a simple line number. An ordinary continuation uses that retained progress. Deliberately selecting a source line creates a new entry instead. These two actions can produce different approaches to the work, even if the same text line is visible on the screen.

Do not choose a later line as a convenient way to skip an unexplained stoppage. Required tool, spindle and other equipment states may depend on earlier instructions. The application prepares supported entry state, but you still have to establish that restarting there is appropriate for the partly machined workpiece. Chapter 18 explains that separate procedure.

Example: inspecting line 80 before the first run

You single-click line 80 to see which part of the outline it represents. That inspection does not ask the machine to start at line 80. If you double-click the line while stopped and the application accepts the selection, you have changed the intended next start. Check the recorded operation and the selected-start procedure before running.

When in doubt, resolve the start intention while stationary. Do not press Run merely to discover where the machine will go. A reliable pre-run explanation is specific: “This is the first run of the checked job,” or “This is an approved continuation after the documented interruption.” Being able to make that distinction prevents a display gesture from becoming an unexpected machining decision.

16.4 Press Run once and follow the response

With the pre-run checks complete and the intended start understood, use the main Run control once. Keep watching for a response. The button's availability is useful information, but its appearance is not a complete readiness certificate. Further checks occur when the application processes the request and when the equipment performs each operation.

Use a simple start sequence

  1. Confirm the final setup.

    Check the job identity, start intention, work origin, tool and required equipment. Clear the permitted movement area according to the machine procedure.

  2. Check the displayed controls.

    Confirm the intended main-program feed and spindle settings. Know where Pause, Reset and the machine's emergency control are before movement begins.

  3. Request Run once.

    Allow the application to respond. Do not double-click or repeatedly press the command because the first cutting line has not yet moved.

  4. Read any warning.

    If the request is rejected, retain its message and relevant job information. Resolve the stated condition before deciding whether another attempt is appropriate.

Table 16-4. Typical reasons Run is unavailable or does not proceed
ConditionMeaningNext check
File preparation is activeThe new program is not yet available for running.Wait for completion or finish the normal cancellation procedure.
Offline or homing incompleteThe machine does not meet the application's homed-motion admission conditions.Check connection and all configured axes, not only the visible cutting axes.
Reset pendingThe earlier stop/reset sequence has not settled.Wait for its result; review recovery before starting again.
Tool or entry warningThe proposed start fails an additional check.Read the specific message and correct the identified setup.

A “Run accepted” entry in the report means that a start, preparation or positioning request was admitted. It is entirely possible for the head to remain momentarily still while the next stage is being established. Stillness alone does not mean the request failed. Conversely, movement somewhere on the machine does not establish that the main cutting program has begun.

If there is no understandable response, stay with the machine, check the report and establish the present state before another command. Record the last accepted action and the warning rather than describing the event only as “Run did nothing.” Those details distinguish an unavailable command, a rejected request and an accepted operation waiting for another stage.

16.6 Understand the approach to the entry position

This approach is real machine movement. It is not just a preview animation and is not necessarily the first programmed cut. When a direct start finds a position mismatch, the application can accept the needed return positioning. That is why an accepted Run may lead to a movement outside the visible beginning of the cutting pattern.

How the reviewed positioning route is arranged

When horizontal movement is required, the reviewed route first moves Z to its configured maximum travel coordinate, travels horizontally at that level, and then moves Z to the destination. The route is constructed with stops between its legs. If no horizontal repositioning is needed within the configured tolerances, the route can consist of a Z movement to the destination.

The configured Z level and travel limits must have been set correctly for the machine. Calling this a clearance route does not mean the software has measured the stock or detected every obstruction. Verify that the tool, holder and head can follow the entire route. The coordinate used for clearance is a machine setting, not a guarantee about an unfamiliar fixture.

Table 16-6. What to observe during entry positioning
StageExpected observationWhat it does not prove
Clearance movementFor horizontal repositioning, Z first travels toward the configured clearance level.That all physical obstructions have been detected.
Horizontal transferThe head travels toward the destination's horizontal position at the configured level.That the main cutting path is already executing.
Final approachZ moves to the entry destination.That the following equipment actions have all completed.
Handoff to the programThe positioning operation successfully allows the main program to proceed.That an earlier accepted request cannot subsequently fail.

The feed slider is not a universal positioning control

The approach operation uses the configured traverse speed on its own positioning path. The main-program feed percentage controls the main machining path. Do not assume that reducing it slows the magazine route or the positioning approach. Before the first Run, understand which controls apply to the operation you are about to observe; Chapter 9 covers positioning commands and their routes.

When positioning finishes, the application uses a controlled handoff to start the main program. If the operation is stopped or its handoff is rejected, arrival near the work is not proof that the program has started. Read the result and re-establish the intended start state. Do not use manual jog to complete the last part of a rejected approach and then assume continuation is automatically valid.

Example: the head is already above the entry area

Only the height differs from the required entry. The approach may therefore be a vertical movement rather than the three-leg route you saw on another job. Compare the actual motion with the prepared destination and current position, not with an expectation that every Run must show the same sequence.

Stay attentive through the transition from positioning to machining. Equipment actions or a tool-related wait may occur before the first cut. The useful question is “Has the expected next stage begun successfully?” rather than “Has enough time passed since I pressed Run?”

16.7 Observe the first cut and maintain a useful monitoring routine

The first cut is where the prepared job meets the actual material. Watch from the designated operating position as the head completes its approach, the expected equipment operates and the cutter begins the intended feature. The first useful comparison is straightforward: is this the expected tool, in the expected area, beginning the expected operation?

Do not focus only on the moving line in the preview. Compare the machine with the approved setup: stock remaining secure, a plausible approach and cutting depth, the required spindle and extraction behavior, and no unexpected contact. Use the machine-specific procedure for an abnormal sound, vibration, material movement or equipment condition. A screen that continues to show progress does not make an unexpected physical condition acceptable.

Read several indications together

The coordinate displays can be especially useful for recognizing the general region and height of the head. Machine coordinates and work coordinates describe the position relative to different references. They are not interchangeable. If you are unsure which values you are reading, revisit Chapter 5 while the machine is in an appropriate settled state.

The feed display can change during acceleration, deceleration, corners and small movements. It need not remain equal to the nominal speed associated with the program. A low reading on a short segment is not, by itself, evidence of a fault. Interpret it together with the current operation and approved cutting conditions.

Keep inspection gestures separate from operating actions

The source view is useful for following progress, but it is not an invitation to modify the job during machining. Some selection functions are unavailable while the controller is busy. If a click does not pick a path segment during execution, do not assume the mouse or job has failed. Avoid changing settings or attempting unrelated motion merely because a display function is temporarily restricted.

Example: progress advances while the expected feature is elsewhere

The line indicator changes normally, but the cutter appears to be working in an unexpected region. Normal display activity does not resolve that discrepancy. Follow the stopping procedure appropriate to the actual condition and identify the file, origin and start intention before considering continuation.

16.8 Use the main-program feed percentage deliberately

The main-program feed control adjusts the velocity factor applied to the main machining path. Its default range is 0% to 120%. At 100%, the factor leaves the prepared feed at its nominal rate. Higher values request an increase within the machine limits. This is a live operating control, so a change can affect an active program without loading the file again.

Choose values according to the approved cutting procedure. This manual does not prescribe a percentage for an unfamiliar material or cutter. A very low cutting feed is not automatically a suitable operating condition, especially if the spindle continues turning at its existing speed. Use the job's permitted conditions and the machine's procedure for first-piece observation.

Understand the percentage without treating it as a speed guarantee

Table 16-8. Main-program feed settings
Setting or actionMeaningPractical implication
100%No reduction from this factor.Actual commanded motion still follows planning, acceleration and machine limits.
50%A factor of one half on main-path velocity.This is not a promise that the whole job takes exactly twice as long.
0%Requests controlled reduction of main-path feed to zero.It does not reset the program or cancel all machine activity.
Increasing above zeroRemoves some or all of that feed reduction.A retained active path can resume without another Run request.
Changing jog feedChanges a separate manual-motion control.It is not the main-program override.

For a simple illustration, imagine a long straight movement whose prepared steady speed is 60 mm/s. A 50% factor corresponds to 30 mm/s for that steady portion. The complete movement also includes acceleration and deceleration, and a real job includes many other operations. Therefore neither the on-screen speed nor total duration has to follow this simple example at every instant.

Zero feed does not end the operation

When feed is reduced to zero, allow for controlled deceleration. The machine does not become physically stationary at the instant you move the slider. More importantly, the main path retains its progress. Raising the percentage can allow it to move again without pressing Run. Treat that increase as an action that can initiate movement.

If you intend to pause or stop the operation, use the defined command and check its result. Pause and Reset have different effects on retained program progress, explained in Chapter 17. Even those motion commands do not by themselves establish every condition required for physical access.

Example: no new Run was pressed, but the head moves

The operator reduces feed to zero during an active cut. Later, while the retained path is still active, the percentage is increased to 30%. Motion can resume as a direct result of that increase. This behavior is expected; the earlier zero value did not cancel the job or create a requirement for a second Run.

Check which control you are changing

After an authorized change, observe its effect and leave the control at an understood value. Recheck the actual displayed percentage before every new job or continuation rather than assuming a previous reset, stop or file load has returned it to a preferred value. The reviewed feed control is a runtime value, separate from the persisted machine settings; it should be treated as part of the current operating state.

16.9 Interpret progress and the nominal time display

The program status combines progress with elapsed, remaining and total time information. These values help you understand the prepared job, but they are not a stopwatch measuring the real duration of the current run. Read them as a nominal timeline for the original whole program at 100% feed.

“Nominal” means a calculated reference under the application's planning assumptions. The actual operation includes the effect of feed changes, preparation, tool and equipment waits, interruptions and other conditions. The displayed estimate cannot predict every one of these. It is useful for orientation and planning, not as a promise of when it will be appropriate to unload the part.

Progress is based on source lines

The progress percentage follows the physical lines of the source document and the execution or selected-start state shown by the presenter. Lines do not all represent equal work. One line can describe a long cut, another a short move, another an equipment action, and some lines are comments. Half the source lines therefore does not mean half the material has been removed or half the real operating time has passed.

The current line can remain unchanged while a long movement executes. Nominal elapsed time is based on completed preceding source blocks rather than continuous measurement of how far the cutter has advanced within the current block. A time value that remains unchanged during visible movement can consequently be expected.

Table 16-9. Read the timing fields as a nominal program timeline
FieldWhat it representsDo not interpret it as
Progress percentageSource-line-based displayed progress.Percentage of finished material or accepted product.
ElapsedNominal time associated with the preceding program portion, including a prefix omitted by start selection.Time on a wall clock since this Run.
RemainingThe original nominal total minus the displayed nominal elapsed value.A live countdown including every future wait and override.
TotalThe original whole-program nominal estimate.A new estimate for only the selected suffix or the actual shift duration.

A worked example

Starting partway through a twenty-minute program

Suppose the original nominal total is 20 minutes. The approved entry you select has 8 minutes of nominal program time before it. At that entry, the screen can show approximately 8 minutes elapsed and 12 minutes remaining, even though you have only just requested this run. The total remains 20 minutes.

The 8-minute prefix has been passed in the displayed program timeline; it was not necessarily machined during this run. If you then use a reduced feed or encounter a tool wait, the real time needed for the remaining operation can differ from the displayed 12 minutes. Do not use this example to calculate a production promise.

Likewise, when a job runs at 50% feed, do not expect the displayed total to become a newly calculated wall-clock duration. The timing fields retain their nominal meaning. A simple “double the remaining time” rule also ignores operations that are not governed by the main-path feed percentage.

To record real production duration, use the shop's approved timing or production-record method. Keep setup time, actual machining time and interruption reasons identifiable. The application's nominal estimate and those records can then answer different useful questions without being mistaken for each other.

16.10 Distinguish an expected wait from a problem that needs action

Start with the last operation you saw, the current source area and the newest report entry. For example, stillness after a spindle-start request has a different context from stillness after an axis warning. The application includes spindle-start delays and readiness checks, and its dwell instruction intentionally waits for the requested interval. An expected wait should have an understandable purpose within the job.

Use the operation context

Table 16-10. Investigating an apparent wait
What you observeCheck firstAvoid
Stillness after a spindle commandExpected start/stop sequence, its status and any readiness warning.Assuming that a speed setting alone proves rotation or standstill.
Main-path feed is zeroThe displayed percentage and whether the path retains active progress.Increasing it without preparing for movement.
Movement continues but source line does not changeWhether the current source line contains a long movement.Treating each display update as a requirement for motion.
A warning or unexpected termination appearsThe full message, termination reason and actual machine condition.Resetting immediately and losing the context needed for recovery.

Equipment requests and feedback are different

A spindle-speed request tells the control system the intended speed. It is not, by itself, a measurement of actual revolutions. In the reviewed spindle-start sequence, success depends on readiness and the configured start delay; it does not certify a measured speed reading. Read equipment indications using the distinctions explained in Chapter 10.

A later programmed speed instruction can update the requested spindle speed. Do not assume that a value you entered manually is permanently protected from the program. Changes during production must be part of the approved operating procedure, with the effect on the current and following operations understood.

For installed equipment, use the configured machine's expected sequence and Chapter 13. Equipment behavior may depend on the installed program and settings. A delay that was normal on another machine is not a reliable explanation for a new unexplained wait on this one.

When the condition is not understood

Do not invent a fixed waiting period after which every operation should be considered failed. Different operations use different delays and feedback conditions. Read the reported result. If the expected sequence does not progress or the state is unclear, follow the approved interruption procedure, retain the evidence and obtain the required assistance before another start.

Pause requests a controlled stop of all motion while preserving the main-program cursor where continuation is applicable. Reset requests all-motion stopping and a main-program reset after stopping. Both also cancel pending preparation continuations. They are not interchangeable with zero feed, and they do not themselves serve as general equipment-off commands. A requested stop still requires observation of the resulting standstill.

16.11 Recognize program completion and any final parking movement

Reaching the last visible feature is not the same as finishing the whole machine operation. The program can still have a withdrawal, equipment shutdown or final instruction to perform. After the main program ends, an enabled automatic parking option can request another movement. Continue monitoring until the actual sequence is complete.

The application distinguishes a naturally completed program from a requested stop, an observed axis or coupling fault, and an ending whose origin is unknown. These are different outcomes. A stopped machine is not automatically a successfully completed job. Read the operation report rather than drawing that conclusion from stillness alone.

Use the termination reason

Table 16-11. End states and the next operator decision
Reported outcomeMeaningWhat follows
Program completed naturallyThe controller reported normal termination of this program execution.Observe any requested park movement, then follow the access and inspection procedure.
Stopped after a requested stopExecution ended in response to a stop request.Review interrupted work and retained/reset state before recovery.
Observed axis/coupling faultThe execution ended with an observed motion fault.Resolve the fault and assess the affected job before restarting.
Unknown stop originThe application cannot classify the ending as a confirmed normal completion.Retain the evidence and investigate; do not accept the job merely because movement ceased.
Park request rejected after completionThe cutting program can be complete while the separate parking request was not admitted.Keep the actual head location in mind and use the approved next procedure.

Automatic parking is a separate following action

When Park Enabled is selected, a confirmed natural completion causes the application to request GoToPark once. Manual stops, faults and unknown stop origins do not trigger this automatic request. The route and configured park location must already have been checked as part of the setup.

If parking is unavailable at that moment, the application reports the result; it does not hold a hidden repeated request that automatically retries later. Do not interpret failure to park as proof that the machining itself was incomplete, or assume that a later unrelated action will finish the park movement. Check the two results separately.

Parking does not own spindle shutdown. Spindle sequencing belongs to the main program. A head that reaches the park position is therefore not, by that fact alone, ready for physical access. Follow the machine's requirements for spindle standstill, other equipment and access before approaching the workpiece.

Why the end display may return to the beginning

The reviewed program-end action M2 requests spindle shutdown and waits for its configured stop qualification. M30 uses that stop operation and resets its source program after successful completion and an idle path. A job ending through this sequence can return the program cursor to its beginning instead of leaving a permanent “100%” display.

You do not need to write these instructions, but it helps to recognize them near the end of an approved file. A return to the beginning can be an intentional program-end result. If the expected end sequence fails, use its warning and actual machine condition; do not infer success simply because the final instruction was reached.

Example: the final groove is finished and the head moves again

The controller reports natural completion, then the head starts toward the configured park position. With automatic parking enabled, this is an expected following operation. Keep the movement area clear until it finishes and check the spindle and equipment state before the normal unloading procedure.

After the machine reaches the required access condition, inspect and record the work according to the job's quality procedure. Program completion confirms a control outcome, not dimensional acceptance of the part. A wrong origin, unsuitable cutter or shifted workpiece can produce an unacceptable part even when the file runs to its normal end.

Before another part, recheck the setup items that may have changed and establish the next start intention. Do not assume the finished program is automatically ready to repeat with the intended tool, cursor and feed value. The next Run is another deliberate operating decision.

16.12 Practise the complete operating sequence and check your understanding

Use this final section to bring the chapter's individual observations into one repeatable routine. Practise first in the approved training environment with a known job and an instructor or responsible operator. A successful Simulation exercise helps you learn the controls, but it does not verify real workholding, cutter condition or machine clearance.

The purpose of the exercise is to describe what is happening and why you are choosing each action. Do not make deliberate faults, tool-state mismatches or unexpected movements on a real machine simply to see a message. The examples below can be discussed from the manual or demonstrated using an approved training setup.

Walk through one ordinary job

  1. Identify the work.

    State the job, file revision and intended operation. Find its file identity on screen and describe the expected shape from the preview.

  2. Connect the screen to the setup.

    Identify the stock datum, selected work reference, first tool and expected entry area. Explain what was physically checked and what information comes only from the screen.

  3. State the start intention.

    Explain whether this is a fresh start or an approved continuation. Show why a highlighted line alone does not answer that question.

  4. Identify the operating controls.

    Locate Run, Pause, Reset, main-program feed and spindle controls. Explain which control affects only manual jog and which percentage can resume a retained active path when raised above zero.

  5. Monitor the transition into cutting.

    Compare the expected tool and starting area with the observed sequence. Describe the current line, commanded position and displayed feed without treating them as independent physical measurements.

  6. Read progress in context.

    Explain the nominal elapsed, remaining and total values. Identify why a long line or equipment wait can make them behave differently from a stopwatch.

  7. Observe the end.

    Read the termination result, follow any park movement and establish the required access state before the normal inspection and unloading procedure.

Table 16-12. Questions an operator should be able to answer
QuestionExpected understanding
Does a single-clicked text row choose the next start?No. Inspection selection and an explicit start request are separate.
Does zero feed let me enter the machine?No. It reduces main-path feed and preserves progress; other activity and energy can remain.
Can increasing feed from zero cause movement without another Run?Yes, while the retained path is active and able to continue.
Does 50% progress mean half the real job time remains?No. Progress follows source lines, which do not represent equal durations or amounts of work.
Why can elapsed time be nonzero immediately after a selected start?The nominal original-program timeline includes the omitted prefix.
Does natural completion establish part quality?No. The part still requires the approved inspection.
Does reaching park establish spindle standstill?No. Parking and spindle sequencing must be checked separately.

Prepare a useful handover

If another operator takes over an unfinished job, communicate the current file, work setup, tool, last confirmed stage and any interruption. Include the actual feed percentage and whether an explicit start line has been selected. Explain what remains uncertain. “It is ready” is insufficient when the next action might continue a partial cut or begin from a newly selected entry.

For a completed job, record the result required by the shop: quantity, inspection outcome and any relevant deviation or interruption. If the next part uses the same file, still verify the replaced stock, workholding and current machine state. Repetition reduces neither the need to identify the work nor the responsibility to observe the start.

You are ready to use this chapter when you can explain the intended start, recognize the preparation stages, interpret the monitoring displays and identify the actual end result. Continue with Chapter 17: Stopping, Pausing and Recovery for the detailed decisions required when the sequence is interrupted.
