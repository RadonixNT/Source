I/O Configuration and Signal Mapping

Understand how a machine function is connected to an electrical channel, how to read its indication, and how to review an authorized mapping change.

23.1 Start with the machine function, then identify its channel

A machine needs information from switches and sensors, and it needs a way to operate equipment such as valves and the spindle drive. These connections are called inputs and outputs, often shortened to I/O. An input brings information into the control system. An output carries a request from the control system to connected equipment. You do not need to write a program to understand this distinction.

For example, a tool-height sensor provides an input: it tells the control system that the sensing condition has occurred. A tool-release valve is operated by an output: the control system requests a change at the valve. The request and the result are different things. A valve output can be On while a separate sensor still reports that the mechanism has not reached its expected position.

A name describes a purpose; an address identifies a connection

A signal name such as Tool Height Sensor describes what the information means to the machine. A channel address such as DM1.IN4 identifies where the software obtains that information. The mapping connects the name to the channel. Think of it as a labelled connection in a directory: “For the tool-height sensor, read this input.” It does not move a wire or change the label on an electrical terminal.

This distinction explains why changing a mapping can have a serious effect without any visible movement at the time of editing. The next operation may read a different switch, or send a command to a different device. A correct-looking signal name is therefore not sufficient. The selected channel must agree with the machine's approved wiring and setup record.

What an operator should learn from this chapter

For ordinary operation, the main task is to recognize the correct signal, read its selected target and report its state accurately. Mapping changes normally belong to an authorized setup or maintenance task. They are not a routine way to clear an alarm, make a disabled button available or compensate for a sensor that does not respond.

Read the chapter in order the first time. It begins with the names and fields, then explains special targets, live indications, filtering, controlled editing and verification. Use Chapter 21 if you need help selecting a Configuration group or entering a value. Use Chapter 22 for the surrounding controller and machine settings. Keep the electrical documentation available whenever an actual channel assignment is being reviewed.

23.2 Find the mapping and understand the fields

Open the Configuration window and follow Controller → PLC → Mapping. The displayed group is called Mapping, even though this chapter uses the fuller term “signal mapping.” Expand the appropriate category, then select the signal by its machine function. Read the complete path before editing: similar words can occur in a module's raw channel view, a machine parameter group and the mapping editor.

The four categories are Digital Inputs, Digital Outputs, Analog Inputs and Analog Outputs. “Digital” means a two-state value, displayed here as Off or On. “Analog” means a variable numeric value. In this editor analog values use a normalized scale from 0 to 1. They are not automatically displayed in volts, pressure units or spindle revolutions per minute.

Table 23-2. Fields within a signal group
FieldMeaningImportant distinction
EnabledWhether the selected target is used for this signal.Turning it off preserves the target text but removes that connection from use.
Input or OutputThe selected channel or special target.Choose from the list; this is not a box for inventing an address.
Filter ModeFiltering selection for a digital input.It concerns recognition of an input, not output speed.
StateThe signal value.Digital values and analog inputs are read-only here; an available analog-output value can be a live command.

The target also appears as identifying information for the group. Do not mistake that displayed address for a separate signal. Some sensor names include a reference in parentheses, such as Spindle Tool Clamped (S1). This helps distinguish the sensor's role; it does not mean that its physical input channel is numbered 1.

Why a category may have no entries

The supplied application profile defines digital inputs, digital outputs and the Spindle Speed analog output. It does not define an analog-input signal. An empty Analog Inputs category is therefore not, by itself, evidence of a connection fault. The application also publishes only the target families provided by its profile. A missing choice must be investigated against the approved machine configuration, not replaced with a vaguely similar address.

Viewing and editing have different availability. Mapping configuration is frozen throughout an online controller session. Stopping a cutting program does not make these configuration fields editable. An authorized change requires an offline configuration state, and an active configuration operation can still prevent editing. Account access can impose additional restrictions. A grey field is a reason to check those conditions, not to keep reconnecting until the editor happens to accept a change.

23.3 Read channel addresses and compare the supplied assignments

Read a target address in two parts. In DM1.IN4, DM1 identifies a digital module in the software profile and IN4 identifies its input channel. In DM0.OUT2, OUT2 is an output channel. Input and output channels with the same number are different connections. DM0.IN2 and DM0.OUT2 must never be treated as interchangeable.

Channel numbering starts at zero. The digital-module choices run from IN0 to IN7 and OUT0 to OUT7. Fresh settings provide DM0, DM1 and AM0. Controller > PLC > Modules exposes Digital Count (0–8), Analog Count (0–2) and Encoder Count (0–2); the defaults are 2, 1 and 0. Stable identities preserve retained UID and Mode values when a module is removed and later added again. These are software module identities; the name alone does not establish a physical board's identity, terminal position or network address. Match them to the commissioned module arrangement and electrical drawing before relying on a channel number.

The inverter is presented differently. INV0.RUN is a digital run request and INV0.SPEED is a normalized speed request. Neither name represents a sensor confirming actual rotation. Where an analog module is provided by a profile, its target names use AM with IN or OUT channels; the supplied profile includes AM0. Controller > Inverters > Inverter Count selects 0–2 inverter slots and defaults to zero.

Several supplied signals begin Unassigned, including the physical Run, Pause and Reset switches, roller and unloader signals, Pressure Sensor, Spindle Piston Retracted (S5), Spindle CCW and Coolant. This is a description of the initial profile, not an instruction to leave equipment disconnected. A machine builder may commission different assignments. Do not overwrite working values to make the screen match this table.

Use the table to ask better questions

If the tool-height indication changes when an unrelated switch is operated, record the signal name, selected target and observed switch. This is more useful than reporting only “the input is wrong.” If a channel is already assigned elsewhere, do not reuse it because its current state looks suitable. The mapping validator rejects duplicate physical channel assignments, and a shared-looking electrical signal still requires an approved design.

23.4 Distinguish disabled, unassigned, fixed and virtual signals

Not every target refers to an electrical channel. The editor also offers choices that keep a value inside the control software. These choices can be useful in an approved machine configuration or training arrangement, but their presence does not make them substitutes for working sensors or connected outputs.

Enabled describes whether this mapping uses its selected target. If you turn Enabled off, the address remains visible and is retained for later use, but the signal uses independent internal storage. This is not the same as commanding the selected output Off. It is also not electrical isolation: a mapping change does not disconnect power, vent a cylinder or prove that another control path cannot operate the equipment.

Table 23-4. What the special choices actually mean
ChoiceWhere offeredEffect
UnassignedAll four signal categoriesNo physical channel is selected; the signal uses its own internal value.
Enabled offEvery signalRetains the target text but uses internal storage instead of that target.
FALSE / TRUEDigital inputsA fixed read-only Off / On value, independent of a physical switch.
Virtual FALSE / Virtual TRUEDigital outputsAn internal output initially Off / On when deployed; its value can subsequently change.
Enabled physical targetMatching input/output familyConnects the signal to the named channel; it does not certify network or equipment health.

Unassigned does not necessarily mean unused

An unassigned signal can still be used by the control logic. The application warns when an enabled unassigned signal is referenced by the successfully validated program information. This warning means that an internal value will be used; it does not mean that the software has discovered the correct missing wire. An optional unassigned signal can appear without that warning. Neither appearance proves that an installed accessory is ready for production.

Internal values must not be assumed to remain Off forever. Simulation or control logic can use internal storage, and virtual outputs are specifically writable values. The words Virtual TRUE describe the initial value, not a permanent On command at a physical terminal. Conversely, a fixed TRUE input stays true regardless of whether a real switch is pressed.

Do not turn a missing condition into a permanent permission

Suppose a tool-clamped sensor is not changing. Selecting TRUE would replace observation of that sensor with a fixed answer. It would not clamp the tool, repair the cable or verify the holder. Report the fault and follow the approved recovery process. The same principle applies to emergency, pressure, drive-ready, thermal and mechanism-position signals.

If a disabled signal still shows a plausible address beside its name, read Enabled before trusting it. If you are comparing two machines, record both the target and Enabled; recording the address alone can hide an important difference. Record special target names exactly as shown, including the word Virtual. Before returning a training or service configuration to production, have the responsible person verify that all required physical signals are restored and tested.

23.5 Read State without confusing an indication with a command

State answers a narrow question: what value is this signal reporting through the application? To interpret that answer, first establish the connection state, the target and whether the mapping is enabled. Only then relate Off, On or a number to the actual machine condition.

For digital signals, On means a true logical value and Off means a false logical value. These words do not have one universal mechanical meaning. A normally-closed circuit can be On in its normal condition and go Off when operated or interrupted. Another sensor may become On only when its target is present. Use the machine's documented expected states; do not decide that every On indication is good and every Off indication is a fault.

The emergency indication is a specific example

The supplied Emergency Switch description states that On means the normally-closed circuit is closed. Off causes the background control logic to request a controlled stop of axis/path motion and block new motion. Releasing the switch does not automatically resume interrupted motion. This screen indication is not confirmation that all motion has stopped, and it does not describe every part of the machine's physical emergency-stop system.

While disconnected, the mapping editor reports physical digital states as Off. That is not a measurement of the disconnected wiring. A fixed TRUE input can still show On offline because its value comes from the fixed choice. If a screenshot is used to diagnose a problem, include whether the application was connected, disconnected or running in simulation.

Panel-button polarity

Run Switch and Reset Switch are NO (OFF released, ON pressed); a release must be seen after connection/remapping. Pause Switch is NC (ON released, OFF active) and is checked immediately when Online begins. An assigned OFF Pause inhibits Run; returning ON never resumes automatically. Disabled/unassigned/fixed-value Pause mappings do not enable this physical-input interlock. The internal Reset Switch identifier remains StopSwitch.

Wiring panel jog buttons

In Configuration, open Digital Inputs and select a command for one of the X, Y, Z, B, C axes. Assign its Input to the physical channel of a normally open pushbutton and enable the mapping. For example, assign Jog X+ to the channel wired to the positive X button. Check the channel state with the button released and pressed. The panel offers single-axis input assignments. Diagonal XY commands remain available on the screen and through keyboard shortcuts.

  • Jog follows the selected jog mode. In continuous mode, hold the button to move and release it to end the request. In step mode, one press requests one configured step.
  • Step Jog requests one step in the chosen direction with each fresh press.
  • GoTo requests the configured machine-coordinate destination for that axis. The machine must be homed. Releasing the button does not cancel an accepted step or positioning move.

The interface samples assigned physical jog inputs on its 20 ms operator timer. After connection or reassignment, release the button before pressing it. A held button does not restart a jog after a Reset, Pause or Run input suppresses it.

An editable analog-output value is live

For Spindle Speed, a value of 0.5 represents half of the normalized request range. If the configured maximum spindle speed were 24,000 RPM, this would correspond to a 12,000 RPM request in the application's speed scaling. This is an explanatory example, not a recommended setting and not a measurement of shaft speed.

Editing an available analog-output State sends a live request. Do not enter a trial number merely to learn how the editor works. The mapping State field is not the same control as the normal operator spindle-speed control and does not use all of that control's availability checks. Use the normal operating controls for production and a supervised procedure for service tests.

Configuration Cancel does not undo live output requests or reverse any physical action. A digital-output State, by contrast, is read-only here; the separate manual controls are responsible for ordinary output requests. Keep these differences clear when asking for help: report whether you changed a target, changed a live analog value, or only observed a digital indication.

23.6 Understand digital-input filtering

A digital input may change very briefly because of contact bounce, electrical interference or a real short pulse. Filtering determines how the input hardware handles short changes before the control logic sees them. The Filter Mode field belongs to a digital-input mapping. It is not a general delay for the whole machine and it does not slow an output valve or spindle command.

The editor provides four named choices. Their descriptions include approximate times. Treat these as an explanation of the filtering modes, not as guaranteed machine stopping times or a complete specification of sensor response. The actual machine behavior also involves the sensor, wiring, hardware and control sequence.

Table 23-6. Filter choices shown by the application
ChoiceApproximate descriptionPractical interpretation
DisabledThe firmware filtering stage is disabled.Not the same as disabling the input mapping.
LowSpeedAbout 100 msA slower filtering mode; brief real changes may not be recognized as expected.
NormalAbout 10 msThe default selection for a new digital signal.
HighSpeedAbout 1 msA faster filtering mode; supplied for Spindle Rotation Sensor.

Why changing the filter is not a general repair

Imagine a switch indication flickering when its mechanism is stationary. A longer filter may change the visible symptom, but it does not establish whether the cause is a damaged cable, loose connection, unsuitable sensor arrangement or genuine movement. Record the symptom first. Have the underlying cause investigated before treating a filter change as an accepted correction.

The opposite problem is also possible. A rotation sensor produces brief events as the spindle turns. A filter selected for a slow mechanical switch may suppress events that the rotation function needs. This is why the supplied profile selects HighSpeed for that sensor. Do not copy that setting to all inputs: different functions require different commissioned choices.

Filtering follows the mapped digital input. If an authorized mapping change moves the signal to another physical digital channel, its filter selection must be reviewed with that move. A fixed or unassigned input has no physical sensor signal for this filter to clean up. Choosing TRUE and changing Filter Mode cannot make a missing rotation sensor into a measured rotation signal.

A useful report contains the conditions

When reporting a suspected input timing problem, write down the signal name, target, Enabled state, current filter choice, expected event and actual observation. State whether the symptom is continuous or occasional and whether it occurs only while another machine function runs. Avoid assuming that a slow screen refresh proves a slow electrical response; the operator display is not a high-speed recording instrument.

Filter Mode is a configuration item and is locked during the online session, just like the target. An approved change therefore follows the offline editing and subsequent verification procedure in the next section. Do not adjust it during production and infer success from the absence of an immediate warning. The affected function must be checked under its approved test conditions before the machine is released.

23.7 Carry out an authorized mapping change in a controlled order

Begin with a specific approved change, not with a list of possible channels to try. You need the signal name, the old and new targets, the required Enabled state, the filter choice for a digital input, the reason for the change and the verification procedure. If those items are unknown, collect the screen information and ask the person responsible for the machine setup to resolve them.

Prepare the machine and the record

  1. Finish or stop the current operation using the normal operating procedure. Establish that the machine is in the condition required for the maintenance task.
  2. Record the existing mapping before changing it. Include the full Configuration path and all configuration fields, not only the address.
  3. Disconnect using the normal application procedure and confirm that the controller is offline. A stopped program with an online controller is not sufficient. Every ToolPath must also be empty and no PLC Apply may be active. Clear TP0 with Clear Tool Path and clear any retained auxiliary programs before editing targets, Enabled or Filter Mode.
  4. Open the exact signal under Mapping. Check the name against the approved change record once more.

Disconnecting communication is a software condition for editing. It does not isolate electrical or pneumatic energy. Any physical wiring work requires the machine's approved maintenance isolation procedure, performed by the responsible personnel. Do not open an electrical enclosure solely because the application says it is disconnected.

Edit one signal and review its result

Select the approved Input or Output from the list. Set Enabled and, for a digital input, review Filter Mode. Each ordinary edit updates the application's working mapping information and its diagnostics. Do not interpret an updated label as proof that a physical device has been tested. While offline, it is still a configuration change awaiting the appropriate acceptance and connection procedure.

Table 23-7. Review before accepting a mapping edit
CheckRequired evidence
Correct signalFull name and category agree with the approved task.
Correct destinationTarget agrees with the electrical and module records.
Correct behaviorEnabled and Filter Mode are explicitly reviewed.
No unresolved mapping errorRead the diagnostic text; investigate duplicate, unavailable or incompatible targets.
Next step definedKnow who will reconnect, test and authorize return to service.

Use the normal Configuration acceptance operation described in Chapter 21 to retain the approved ordinary edits. Pending-change presentation compares the target, Enabled state and filter with the saved baseline. A pending indication is about unsaved configuration; a valid indication is about the checks the application can perform. Neither is a commissioning certificate.

If you decide to abandon ordinary dialog edits, use Cancel and then inspect the mapping again to confirm the restored configuration. This applies to edits tracked by that dialog. It does not undo live analog-output requests, physical movement or separate direct operations such as an import/export workflow. Keep those operations out of a simple mapping edit unless they are explicitly part of the authorized task.

After acceptance, reconnect through the normal procedure and follow the supervised verification plan. Do not start a production program as the first test of a changed home sensor, spindle command or tool-release connection. If a change fails validation or the expected response is not obtained, stop the commissioning sequence, preserve the observed information and resolve the cause before continuing.

23.8 Interpret diagnostics, verify the response and record the result

The application checks whether a mapping is structurally acceptable: whether the target is known, belongs to the right signal family, refers to a configured module and avoids duplicate physical assignments. It cannot determine from the address alone whether a technician connected the intended sensor to that terminal. Software validation and physical verification therefore answer different questions.

Table 23-8. Common findings and the appropriate next step
FindingMeaningNext step
Unknown or incompatible targetThe target cannot serve this signal type.Compare the selected value with the approved configuration; do not substitute another type.
Module not configuredThe target's module is absent from the controller configuration.Have the module arrangement checked; a target name does not add hardware.
Duplicate physical channelMore than one enabled physical mapping uses the same target.Identify both signals and resolve the intended assignments.
Unassigned warningA referenced enabled signal uses internal storage.Establish whether that is intentional for this machine.
Valid or inactive presentationThe mapping passed the relevant checks, or is disabled/unassigned as described.Read the explanation; neither status proves correct wiring or function.
Expected indication does not changeSeveral causes remain possible, including connection, mapping or hardware.Record the exact condition and arrange a controlled investigation.

Check an input and an output differently

For an input, the responsible person should create the approved test condition and observe whether the intended signal changes in the expected direction. Where the procedure requires it, verify the return to the normal condition as well. The operator should not reach into a moving mechanism to obtain an indication. An expected screen change is useful evidence only when the selected target and actual test condition are known.

For an output, use the approved operating or service control and observe the equipment response, together with any separate feedback signal. Mapping State is read-only for digital outputs; do not expect to toggle that row. Avoid experimental analog-output commands. A run request does not prove spindle rotation, and a release request does not prove that a tool is released.

Simulation can help explain these relationships, but simulated feedback is not a test of physical wiring. Similarly, a physical-looking target does not by itself confirm that the module is online and healthy. Record the operating mode and connection state alongside the test result.

Leave a useful handover record

Record the date, machine identity, person authorizing the change, signal path, previous and final target, Enabled state, filter selection, diagnostic text and test performed. Describe the observed result in plain language: which sensor condition was created, which indication changed, which output was requested and what mechanism actually did. Include any unresolved issue and whether the machine has been released for production.

If the result is unexpected, stop the test and preserve this record. Do not repeatedly change channels, select fixed TRUE inputs or disable required feedback to obtain a successful-looking screen. Recovery should restore a known approved configuration and include whatever verification the responsible person requires. The chapter is complete when you can explain not only where a signal is mapped, but also what evidence confirms that the intended machine function works.
