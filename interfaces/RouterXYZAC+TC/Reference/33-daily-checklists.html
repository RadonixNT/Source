33.1 Use and record a checklist correctly

A checklist helps you avoid missing a familiar step when you are busy, interrupted or taking over from someone else. It is not a substitute for learning the procedure. If an item mentions homing, work references or tool measurement and you are unsure what to do, follow the linked chapter before completing the item. Do not guess simply to finish the sheet.

Each checklist has a Result / note column for a handwritten or separately recorded result. These are printable forms, not live controls connected to the machine. Marking a row does not change software readiness or authorize motion. Use the browser's print preview to select the relevant pages; the layout starts each section on a new printed page and keeps table rows together where space permits. Check the preview for your selected paper size before printing.

Table 33-1. Recording a result
MarkMeaningRequired follow-up
OKYou performed the check and confirmed the stated condition.Add a value or reference where it is useful, such as the program revision or tool number.
HOLDThe condition is not satisfied or remains uncertain.Do not proceed with the dependent operation. Record the reason and inform the responsible person.
N/AThe item genuinely does not apply to this installed machine or approved job.State why. Do not use N/A for a check you could not perform.

Check the condition, not just the button

“Homing checked” means the required homing procedure has completed and the resulting state is confirmed. It does not mean that you pressed Home. “Tool checked” means the installed tool and its required confirmation agree; it does not mean that a requested tool number appears in a selector. Record outcomes rather than intentions.

A result is valid for the condition you checked. Changing the tool, moving the workpiece, editing the program, changing a reference or reconnecting the controller can invalidate earlier checks. Repeat the affected checks before continuing. You do not need to repeat unrelated paperwork merely because time has passed, but you must account for what changed.

Keep machine-specific requirements with the sheet

The machine supplier or site must define physical power-up, guarding, workholding, utilities, inspection limits and isolation procedures. This chapter cannot specify a pressure, clamp force, clearance or maintenance interval without the installed machine's requirements. Reference those requirements on the sheet rather than inventing a value.

If an item cannot be confirmed from the normal operating position, use the approved inspection or isolation procedure. An indicator in the application is not a substitute for a required physical check. Conversely, a physically correct setup does not replace software preparation such as selecting the correct file and work reference.

Record header for every sheet
Machine: ____________________ Date / shift: ____________________
Operator: ____________________ Job / part: ____________________
Applicable site procedure / revision: ____________________
Unresolved items and person notified: ________________________________________

Retain completed sheets according to the site's recordkeeping practice. They are an operator record of checks, not an automatic machine log or a certificate that every possible fault has been excluded.

33.2 Start-of-shift and machine-readiness checklist

At the start of a shift, establish what condition the previous operator left behind. A machine that looks idle may have an interrupted program, a tool operation awaiting recovery or feed set to zero while an operation remains active. Read the handover before issuing a command. If no reliable handover is available, treat uncertain items as HOLD until they are resolved.

Perform physical checks in the order required for the installed machine. Some checks belong before power-up; others require a connected controller or an approved test. The following list groups the questions to answer and does not replace that machine-specific order. Do not cycle equipment or test an emergency function by an improvised method.

Connection is one stage of readiness

The application validates machine settings before attempting connection. A rejected configuration is not cured by repeatedly pressing Connect. Likewise, a successful connection does not establish the work reference, verify the loaded job or prove that all preparation has finished. Use Chapter 3 for startup and Chapter 6 for homing.

The run-admission checks include connection, homing and the absence of conflicting operations. They help prevent inappropriate commands, but they do not inspect the workpiece or check part quality. Do not treat an enabled Run button as the final sign-off for the physical setup.

Example of a HOLD decision

The previous operator notes that a tool exchange was interrupted. The application opens and connects, but that does not finish the exchange. Record HOLD against tool state, retain the last confirmed stage and follow the approved recovery procedure before job preparation. Avoid changing the current-tool indication simply to make the screen agree with an assumption.

33.3 Prepare a job and verify the first workpiece

A new job needs its own preparation even when the machine was used successfully earlier in the shift. The file, stock, workholding, origin, tools and entry plan must agree. The same file name can refer to revised contents, and the same tool number can contain a replacement cutter. Record enough information to distinguish this setup from the previous one.

Use the detailed procedures in Chapter 8, Chapter 14, Chapter 15 and Chapter 16. A preview helps inspect the planned path but cannot prove that the physical stock, clamps or tools match it.

A start request can include preparation before cutting

The application can accept a start while positioning or tool preparation is still pending. Watch the operation through those stages. A “Run accepted” report is not proof that cutting has begun. If a warning appears or the operation stops, preserve the details and establish the last confirmed stage before deciding what to do next.

For an ordinary new job, follow the intended beginning of the program. Starting at a selected line requires the separate procedure in Chapter 18; it is not a shortcut around an unresolved preparation problem. Record any deliberately selected entry and its reason.

Release the process only after the required inspection

Program completion does not check dimensions, finish, depth or the suitability of the material. Use the site's first-workpiece inspection criteria and record the result separately from the software outcome. Do not invent an acceptance tolerance from the displayed coordinates.

If a correction changes the program, reference, tool or workholding, repeat the affected preparation and first-piece checks. A previously acceptable part does not validate a changed setup. If the change is outside operator authority, leave the job on HOLD for the responsible person.

33.4 Check tool changes and interrupted work before continuing

Use this sheet whenever a tool is changed or measured, work is interrupted, the head is moved away, or an important setup condition changes. The question is not simply “can I press Run?” It is “what state remains, what changed, and which procedure now applies?” Record those answers before continuing.

Pause requests a stop while preserving the main program cursor. Reset also schedules a main-program reset after the relevant idle condition is reached. Both can cancel managed positioning, tool or unloading sequences. A tool operation interrupted by Pause is therefore not automatically a resumable ordinary cut. Use Chapter 17 to establish the recovery path.

A tool number is only part of the evidence

The application can record a newly clamped tool before the complete return sequence has finished. The correct current-tool number does not establish that every compensation and positioning stage succeeded. Check the last confirmed stage in the report and follow Chapter 11. For measurement, use Chapter 12 and confirm which measurement was performed and accepted.

Do not remeasure or exchange tools merely to remove uncertainty about the previous event. First establish the physical state and an authorized recovery sequence. A sensor indication is evidence about a signal; it does not replace the required verification of the mechanism.

Record feed override explicitly

Zero feed is not the same as a completed Pause or Reset. An active operation can remain ready to move when its override is raised. If feed was reduced, write down the retained setting and operation state. Do not hand the machine over with the vague instruction “it is paused” when only the feed was changed.

After an emergency or connection interruption, re-establish readiness and homing as required; releasing the emergency device or restoring communication is not a restart command. If a workpiece or reference moved, the original continuation plan may no longer be valid.
