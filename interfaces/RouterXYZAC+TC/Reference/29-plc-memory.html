PLC Memory and Variables

Inspect a requested memory range, recognize the different value types and report live values without changing the machine's internal data.

29.1 Understand what a memory view can tell you

A variable is a named value used by the machine-control logic. It can represent a count, a calculated number or an On/Off condition. Memory is where those values are held while the control system works. The PLC memory window shows numbered storage locations rather than a list of friendly machine-function names.

An operator usually opens this view at the request of a technician who knows which type and index to inspect. You do not need to read PLC instructions to record a specified value accurately. You do need to know that an index alone is not enough: the value type, deployed program configuration and current machine condition also matter.

Open the dedicated window

The command is OpenPlcMemory, with the supplied shortcut Ctrl+Shift+Alt+M. Use it from the active main window after checking the saved assignment and keyboard-enabled setting described in Chapter 24. The resulting window is titled PLC memory. Opening it does not connect the controller, initialize memory or run a program.

A separate combined PLC monitor also has a Memory tab. Its arrangement is different from the selectable-range table in this chapter. Identify the dedicated window by its Start index and Cells controls and the four columns Index, INTEGER, REAL and LOGIC word (hex). Include the window name when sending a screenshot.

Observe rather than repair through raw numbers

The dedicated memory window has no action for writing a cell, forcing a condition or clearing a stored value. Selecting a row is not a machine command. Start index and Cells affect only what is displayed. Close ends this window's observation; it does not erase variables or stop the controller.

Do not infer that a suspicious value should be changed to zero. Zero can mean a valid position, a false condition, an empty count or something else entirely, depending on the named variable. A raw value is evidence to interpret in context, not an instruction to alter machine state.

Before inspecting an active operation, keep normal machine supervision in place. The window can remain open while the main application works, but it does not replace the normal status display or operating controls. Start with a specific question and the exact range requested by the responsible person.

29.2 Select the requested range without changing memory

The two controls above the table choose which storage indices you see. Start index is the first index displayed. Cells is the requested number of consecutive rows. Changing either control rebuilds the table for that range; it does not write to any of the displayed storage locations.

The default selection starts at index 0 and shows 16 cells. If window-layout saving is enabled, a previous range can be restored when the window is reopened. Always read the actual controls before reporting values. Do not assume that the top row is index 0 simply because you have just opened the window.

Follow a specific range request

  1. Confirm the requested value type, start index and number of cells.
  2. Enter the Start index and commit the entry through the normal field interaction.
  3. Select Cells from the list of 1 through 64.
  4. Check the Index column to confirm the actual first and last displayed rows.
  5. Read the footer to establish whether live memory is available.

The value families do not have identical row ranges

The current controller provides 4,096 INTEGER cells and 4,096 REAL cells, numbered 0 through 4095. LOGIC storage is packed into 64 words, numbered 0 through 63. Each word contains 64 individual logical values. Consequently, an index that is valid for INTEGER or REAL can be beyond the LOGIC word range.

For example, at row 100 the INTEGER and REAL columns can show values, but the LOGIC word column has no word 100 to show. Its dash is not a false logical value. If a technician asks about logical value 100, that does not mean selecting LOGIC word index 100. The next section explains the distinction.

The table displays at most 64 rows per selection. Near the end of numeric storage, fewer rows can appear than the requested Cells value. This boundary behavior is not evidence of a communication failure. Check the final Index before reporting missing rows.

A saved display range is only a viewing preference. It is not a saved copy of the memory values and does not freeze them. Reopening the same range later reads the currently available runtime values, which may have changed with machine operation or a new controller session.

29.3 Interpret INTEGER, REAL and packed LOGIC values

The three value columns represent separate storage families. The INTEGER and REAL values beside index 12 are not two different ways of displaying the same number. They are the contents of integer cell 12 and real-number cell 12. LOGIC word 12 is another separate storage location containing multiple true/false values.

Table 29-3. Value types in operator language
ColumnWhat it containsHow to report it
INTEGERA whole-number value, which can be positive, negative or zero.Include the sign, full number and integer index.
REALA numeric value that can contain a fractional part.Copy the displayed precision and any exponent; include the real index and known unit.
LOGIC word (hex)A group of 64 true/false values displayed as one hexadecimal word.Copy the full value beginning with 0x and identify the word index.

A REAL value does not supply its own unit

A real number may represent a distance, time, speed, ratio or another quantity depending on its definition. The memory table does not attach a unit or descriptive name. A displayed 0.5 is not automatically half a millimetre or half speed. Obtain the variable meaning from the deployed configuration or the responsible technician.

The display preserves substantial numeric precision. A long decimal tail is not, by itself, evidence of an error, and a compact value containing E uses exponent notation. For instance, 1E-3 represents 0.001. Do not round a value in a technical report unless the recipient asks for a rounded measurement; copy the displayed text or provide a clear screenshot.

One LOGIC word contains many conditions

The prefix 0x identifies hexadecimal notation. It is a compact way to show a set of bits, where each bit holds one false/true condition. A word of 0x0000000000000000 has all 64 bits clear. A word of 0x0000000000000001 has its lowest bit set. These examples explain the notation, not the machine meaning of those bits.

The relationship between a word index and an individual logical index is:

Logical index = (word index × 64) + bit position
Bit positions within a word: 0 through 63
Example: word 1, bit 0 → logical index 64

The first word therefore covers logical indices 0 through 63, and the second covers 64 through 127. A nonzero word means at least one bit is set, not that every condition in that word is true. Unless trained and specifically asked to interpret a bit, report the whole word and let the responsible person decode the relevant condition.

None of these values is automatically a physical input or output channel. Logical memory and raw I/O channels are separate concepts. Use the mapping and I/O views when the question concerns a named switch, valve or drive channel, and use this typed memory view when the requested observation is an internal storage value.

29.4 Relate a raw index to a named variable and the correct version

A name gives a value meaning; an index gives it a storage location. The memory window provides the location and value, but not the full relationship to the source document. Before using a row to diagnose a machine function, the responsible person must identify the named variable, its type and its location in the deployed configuration.

Do not use a remembered index from another machine as proof of what a row means here. Shared definitions, program content and prepared program sets can differ. After source changes, validation or deployment, an earlier address reference needs to be checked again against the version that actually runs.

Configuration and live memory answer different questions

A Configuration field can hold a retained machine parameter, while a PLC variable can be a changing runtime value or a value supplied to the PLC by the application. Some application-owned parameters are read-only to the control logic, even though an authorized operator may edit their original Configuration field. Other live values have their own explicit editing rules.

It is therefore unsafe to infer edit permission from the fact that a value appears in memory. This window is read-only regardless of the underlying variable's purpose. If an approved change is needed, use the named field or operating control specified by the procedure, with its normal limits and availability checks.

A source declaration is not a live reading

The text in Shared or another source document describes definitions and instructions. It is not a constantly updated display of each variable's present value. Changing a number in source is a source change, not the same thing as entering a live value in a diagnostic table. Chapter 27 covers the separate validation, saving and deployment steps.

Likewise, pending source changes can coexist with the older deployed program set. The raw memory you observe belongs to the runtime being read, not automatically to the newest text in the editor. If Pending changes is reported by the program monitor, resolve the version question before attaching a newly calculated address meaning to a memory row.

A useful request from a technician is specific: which named variable, which type, which current index and what machine condition to observe. If those details are missing, gather the visible range and connection information first, then ask for the precise location. Searching random values for a number that looks familiar is not a dependable diagnosis.

29.5 Understand live updates, unavailable values and timing limits

The dedicated window reads memory on a nominal 500 ms display timer while visible and not minimized. This is an observation rate for the user interface, not the PLC's control-cycle time. A value may change many times between two screen updates, and display scheduling can delay an update further.

The footer explicitly describes Independent live reads. The cells are read separately rather than frozen together at one exact PLC scan. Two related values appearing on the same screen may therefore have been read on opposite sides of a change. Do not use one screenshot to prove the exact order of a fast internal sequence.

Table 29-5. Display conditions and their limits

Unavailable is not a memory reset

If the controller disconnects, the form replaces displayed values with dashes. It does not command the controller to set those cells to zero. During a configuration-application operation, memory can also be marked unavailable while the footer still names an online connection. Read the full message before diagnosing a cable or board fault.

After restoring availability, allow a fresh display update before recording the values. An earlier screenshot remains a historical observation, not a statement about the current machine. Include whether the application was in simulation or normal operation, because simulated values cannot prove a physical sensor or mechanism responded.

Choose an appropriate observation task

This view is useful for checking a requested stable value or a condition that lasts long enough to observe. It is not an oscilloscope, a trace recorder or a history of every value written. If the issue concerns a short pulse, intermittent transition or precise ordering, ask the responsible technician to select a suitable capture method.

Do not repeatedly trigger a machine operation solely to catch a value changing on this screen. Each operating action needs its normal authorization and preparation. A missed display transition is not evidence that the PLC failed to process the event.

When collecting a comparison, record the range, value type, operating condition and approximate time for each observation. Describe it as a before/after observation rather than asserting simultaneous changes. This makes the evidence useful without claiming timing accuracy the memory window does not provide.

29.6 Collect a reliable observation and report unexpected values

Use a repeatable process when a technician requests memory information. The objective is to supply the right typed value under known conditions, not to change the value until it looks plausible. A careful observation can help separate a program-state issue from a display, connection or address-selection mistake.

Observation procedure

  1. Confirm the requested variable or memory family, index and range against the current deployed configuration.
  2. Open PLC memory and check the actual Start index and Cells settings.
  3. Read the footer. If memory is unavailable, record that condition instead of interpreting dashes as values.
  4. Locate the requested Index and read only the intended type column.
  5. Observe the machine condition specified by the authorized procedure. Do not initiate additional motion merely to populate a report.
  6. Capture the full displayed value, range controls and footer, or transcribe the value with its type and index.
  7. Record the physical observation and any related report message separately from the memory reading.
Table 29-6. What to include in a memory observation
InformationExample of the detail required

RangeActual Start index, Cells and selected row.
Type and valueINTEGER, REAL or LOGIC word; preserve signs, precision and hexadecimal digits.

Operating conditionWhat operation was underway and when the observation was taken.

Check simple interpretation errors first

If the reported value looks wrong, verify the column before drawing a machine conclusion. Reading a REAL value from the INTEGER column at the same index is a different observation. For a logical condition, confirm the word and bit rather than treating the whole hexadecimal word as a single true/false switch.

If a row is missing near index 4095, check the storage boundary. If a LOGIC cell shows a dash at a high numeric index, check the smaller word range. If every value is unavailable, investigate the connection or ongoing configuration operation before assuming memory corruption.

If the value still differs from the approved expectation, preserve it and refer it to the responsible person. Do not change source definitions, mapping targets, sensor states or machine parameters as a trial correction. Those changes can alter the conditions being investigated and make the original evidence harder to interpret.

End the observation without implying a machine action

Close the window when it is no longer needed. Closing stops this display's polling but does not reset counters, clear logical conditions or stop a running program. Any required machine stop, fault recovery or approved parameter change must use its own normal procedure.

At handover, state what was observed, what meaning has been verified and what remains uncertain. “REAL index 32 showed this value while waiting for the sensor” is more useful than “memory was wrong,” provided the index reference is current. Accurate labels and known conditions turn a technical-looking table into useful operator evidence.
