Viewing and Editing PLC Source

Find the machine-control document, read its status and follow an approved text-change procedure without confusing saved instructions with the program currently loaded.

27.1 Understand PLC source as machine instructions

The PLC is the part of the control system that manages machine sequences and conditions: for example, checking a sensor, waiting for a spindle condition or coordinating a homing operation. Its source is the written set of instructions used to prepare those functions. You do not need to understand every instruction to locate the correct document, report an error or assist an authorized technician.

This source is different from the machining file opened for a particular workpiece. Editing a G-code job changes that job's instructions. Editing a PLC document can change machine behavior across many jobs. A small-looking change to a condition or delay can affect how the machine responds to sensors, tool release or a stop request.

Three different activities

Table 27-1. Viewing, editing and deploying
ActivityMeaningWhat it does not establish
View sourceRead the stored/working instruction text and its status.That every visible line is the version currently executing.
Edit and validateChange the working text and ask the software to check it.That a valid change is mechanically correct or already loaded.
Deploy and verifyLoad an accepted executable set through the supported controller lifecycle and check its behavior.That saving text alone completed the task.

For ordinary operation, viewing and reporting are the expected tasks. A source change should come with a precise approved instruction: which document, what text changes, why, and how the resulting machine behavior will be verified. Do not experiment by removing an unfamiliar line that appears next to an error. A diagnostic may be caused by another line, a shared definition or a mapping.

The editor's availability follows your effective settings access. A read-only document can be inspected but cannot be changed at that level. An editable document is not proof that an operator should redesign its sequence. Obtain Engineering access when the authorized task requires it, as described in Chapter 25, and respect the separate machine-state requirements.

Before planned source work, finish or stop the current operation through the normal procedure and arrange a service period. Keep the approved source record available. If a running machine has a fault, first make it safe using its operating procedures; opening a code editor is not a recovery action that stops motion.

This chapter explains how to identify a document, read its diagnostics and distinguish the stages of a change. It intentionally does not provide replacement interlock logic or programming exercises. For an operator, knowing when to preserve a message and call the responsible technician is as important as knowing which editor to open.

27.2 Find the document in the Configuration catalog

Open Configuration and expand Controller → PLC. Source documents are arranged under Shared Variables, Cyclic Programs and Command Programs. Select a named source entry to display its text in the code editor. Read both the group and the document name before making any change.

Shared Variables contains the Shared source document, which provides information used across programs. This group can also contain ordinary application settings such as Maximum Spindle Speed. Selecting a numeric parameter is not the same as opening the Shared source. Do not replace a simple approved parameter adjustment with a text edit.

Cyclic Programs contains Background. It supplies repeatedly evaluated machine conditions and interlocks. Its description specifically includes emergency-related motion holding, spindle shutdown, brake and tool-change interlocks. The fact that it is only one entry does not make it less significant than the longer command list.

This table identifies the catalog, not an instruction to execute each entry for practice. Some entries support other operations and are not intended to be started independently by an operator. Similarly, an M4 document being present does not prove that the installed spindle supports reverse operation.

Factory text and this machine's text may differ

The application includes initial source text for its selected documents, but previously accepted machine settings can supply saved replacements. The text shown on a commissioned installation may therefore differ from a software factory example. Preserve the machine-specific record and confirm which version the technician intends to change.

The program catalog is explicitly selected by the application. The Configuration editor is not a file browser that automatically turns every source file in a directory into an active machine program. Copying a file beside the application is not a documented method for adding a new command. If the required document is missing, report the catalog and application version rather than modifying another entry with a similar name.

27.3 Make only the approved change and review the text

Before typing, obtain an approved change instruction that names the document and the exact intended modification. “Make the sensor work” is not enough information for an operator to alter a sequence. A useful instruction identifies the previous text, replacement text, reason, affected machine function and verification owner.

Keep a recoverable approved copy or record through the site's configuration-control procedure. Do not assume that another installation's source is suitable because the machine looks similar. Channel mappings, spindle feedback and mechanical arrangements can differ. Replacing a whole document can remove machine-specific provisions that are not obvious from its title.

Work on one document at a time

  1. Place the machine in the agreed service condition and open the correct source entry.
  2. Confirm the full path and document name against the change instruction.
  3. Locate the specified passage before selecting or replacing text.
  4. Make the single approved change. If a replacement document is supplied, verify its origin and intended machine before inserting it.
  5. Review the surrounding text to ensure that the selection did not remove additional lines.
  6. Wait for validation feedback and record any new diagnostic before proceeding.

The code editor writes changes into the application's working source as you edit. It is not the keyboard-shortcut editor, where a separate Assign button accepts a candidate. Selecting a different source does not make the previous text change disappear. Use the ordinary Configuration acceptance or cancellation process deliberately.

Use editor assistance as assistance

Syntax colors, line numbers and completion suggestions help locate and enter text. They do not authorize a change or establish that it will operate the machine correctly. A suggested name may be a real signal while still being the wrong signal for the intended operation. Read the instruction and relevant machine documentation instead of selecting the first plausible suggestion.

Do not change an interlock condition to a permanently true value, remove a timeout or disable a check merely to silence a diagnostic or make a test complete. Those actions change the machine's decision process. If the approved instruction does not resolve the observed problem, preserve the current evidence and return it to the responsible engineer.

If the editor is read-only, inspect the access and current state instead of seeking a different route to modify the same document. When a prepared machining program prevents validation, treat clearing or rebuilding it as a separate coordinated operation; a loaded but stopped job can still matter to configuration availability.

27.4 Read validation messages without guessing a repair

Validation checks whether the current source and its related configuration can be prepared for the controller. The editor validates when a document is shown and schedules another check after edits. Pending validation is also completed when the editor needs to finish it before saving or changing selection. A brief delay after typing is therefore normal.

The check covers the complete PLC candidate, even when you are looking at one document. Programs share definitions, configured signals and other resources. An error associated with a change can therefore involve another document or an I/O mapping. Do not assume that the last line you typed is the only possible cause.

Read the location and the explanation together

A diagnostic can report a document, line and column. The line identifies the row of source text; the column identifies a position within it. These are positions in the PLC document, not line numbers in the machining job. Record the complete document name, location and message before changing anything else.

Table 27-4. Interpreting source status
Status or messageMeaning for review
Waiting for validationThe current working source has not yet received a completed check.
Line and column errorA diagnostic identifies a problem to resolve; an individual rejected program draft is excluded from the next upload.
WarningRead the explanation and resolve or explicitly assess it; color alone is not enough.
Source is validThe source passed the relevant software checks; physical behavior still needs verification.
Valid but disabledThe program is valid but not enabled; validity and execution are separate.
Currently runningRuntime activity is being reported; this does not mean all new draft text has been deployed.

Compilation errors and runtime errors are different. A compilation error concerns preparing the instructions. A runtime fault occurs when a loaded program executes. Saving a text correction is not proof that a runtime fault has cleared, and reconnecting without resolving the underlying cause is not a general repair.

A saved draft can still be rejected

The application intentionally allows some rejected individual program drafts to remain editable and to be saved when a usable validated set still exists. The error message can say that the draft is excluded from the next PLC upload. That is a significant limitation: saving the Configuration window does not prove that every catalog program will be loaded.

Shared-configuration failures, including blocking mappings or shared-definition problems, can prevent acceptance more broadly. Do not generalize from one successfully saved erroneous draft to another case. Read the actual result and report every affected function before any deployment or machine test.

Validation can also be unavailable while prepared ToolPaths still contain blocks. A stopped job is not necessarily an empty controller configuration. Coordinate the appropriate clearing or rebuilding procedure with the responsible person rather than repeatedly editing text to clear an availability error.

27.5 Distinguish saved source from the loaded program

There are three records to keep separate: the source you are editing, the executable candidate produced by validation, and the program set currently loaded in the controller. These records can differ during an authorized change. An operator should never infer which version is running from the editor text alone.

Table 27-5. What each step confirms
StepConfirmsDoes not confirm
Edit sourceThe working text has changed.Saved settings or new controller execution.
ValidateThe software has checked the candidate and prepared the valid executable content.That this content has replaced the online program set.
Accept ConfigurationThe accepted ordinary settings/source changes are retained through the Configuration workflow.That every draft is valid, loaded or physically tested.
Load through the controller lifecycleThe controller receives the eligible program set.That the intended machine behavior has passed its commissioning checks.

Saving is not an online upload button

Use the normal Configuration OK operation to accept the approved source changes after reviewing diagnostics. In the reviewed RouterXYZAC+TC interface, Configuration acceptance validates source properties; it does not present a separate PLC Apply command that immediately replaces the online program set. The read-only PLC programs window also has no Apply button.

The controller supports a separate complete-program-set application mechanism, but that underlying capability should not be mistaken for an operator control on this screen. Do not look for an undocumented shortcut or assume the general Configuration acceptance action invokes it. Follow the installed interface's approved deployment procedure.

For this interface, a new controller connection loads the available validated PLC content through connection initialization. Plan a normal disconnect/reconnect only when the machine is in the approved service condition and the intended source set has been checked and saved. Connection success alone is not proof of PLC completeness: the controller can come online with an empty PLC set when no validated executable image is available, and rejected individual drafts can be omitted from an otherwise usable set.

Verify the loaded state explicitly

After the approved connection procedure, inspect the PLC programs monitor and relevant report messages. Confirm that required programs are loaded, that pending changes have been resolved as intended, and that no load or runtime fault is reported. An apparently normal network connection is insufficient evidence for returning the machine to production.

The monitor distinguishes Offline, Not loaded, Running, Error and Pending combinations. A loaded idle program can have a blank State cell when no pending change or fault is present; do not interpret blank as a universal error. Conversely, Running / Pending means activity and a difference from deployed configuration can coexist.

Do not run the job just to discover whether a source upload worked. First establish that the expected program set is present, then perform the agreed function checks under supervision. A successful validation protects against certain text/configuration problems; only the approved machine verification can establish the intended behavior of sensors, timing and mechanisms.

27.6 Cancel an edit, verify a change and prepare a useful service report

If you decide to abandon ordinary source edits before accepting the Configuration dialog, use its Cancel operation. The dialog restores its tracked edits and asks the application to validate the restored PLC sources again. Reopen the relevant document and compare it with the intended original text before considering the rollback complete.

This cancellation concerns the dialog's tracked changes. It does not undo a separately completed import, a password or board-lock operation, a deployed program set or a physical action. Do not combine several unrelated administration tasks in one visit and assume that a single Cancel reverses everything.

Esc is not a whole-document rollback procedure

A key used to dismiss a popup or stop an editor interaction must not be treated as proof that a source document was restored. Use the explicit Configuration cancellation workflow for abandoning the tracked session edits, then inspect the text. If Configuration has already been accepted, restoring an earlier source is a new controlled change, with validation and deployment review.

Report the stage at which the failure occurred

“The PLC does not work” leaves several different possibilities. State whether the document could not be opened, the editor was read-only, validation was unavailable, a diagnostic rejected the draft, a required program was not loaded, or a loaded program faulted when used. Each observation points to a different next investigation.

Include the line and column when the error supplies them, and capture the report text before another edit changes the location. A screenshot should include the selected document and explanation. For a runtime problem, include the program name, last result or fault information and the machine operation that preceded it. Avoid reporting only a colored symbol or a number without its label.

Verify the affected function, not just the absence of red text

Agree the verification procedure before deployment. A change to tool release needs the applicable tool-handling checks; a change to homing needs the applicable homing verification. Successful execution of an unrelated program cannot verify either. Simulation can help review logic in its supported model, but it cannot prove correct physical wiring, sensor operation or mechanical timing.

If the observed behavior differs from the approved expectation, stop the test using the normal procedure and preserve the evidence. Do not keep editing until the machine appears to accept the request. Return to the approved baseline through a controlled restoration if directed, and verify that restored configuration as well.

At handover, make clear which version is saved, which version has been loaded and what was actually tested. Leave no ambiguity such as “the new text is there, so it should be running.” The source editor is useful to an operator when it helps identify and communicate the machine's configuration accurately; responsibility for an unverified logic change remains with the authorized engineering process.

Adding custom command programs

Select Command Programs or one of its children to enable Add on the main Configuration toolbar. Remove is enabled only for a removable custom program; factory programs cannot be deleted. An empty Command Programs branch can still be selected to add the first custom program.

Changes require an inactive controller and cleared ToolPaths. Program names and source use the existing settings persistence. Cancel restores the program list and source draft. Referenced programs cannot be removed until their dependencies are corrected. A custom M program such as M15 becomes available to G-code after configuration is accepted; the path waits for its execution and completion.

Hardware counts and PLC source are validated together. A removed module, inverter or axis must not remain referenced by active source or mapping. Comments and quoted text do not define module or inverter dependencies. A failed validation does not commit the draft hardware topology.

Operator command extensions

Command Programs contains editable Run, Pause and Reset PLC documents. Screen controls, keyboard shortcuts and assigned panel inputs use the same commands. The extension is queued after command acceptance, not after physical motion has finished. Pause/Reset request all-motion stop first; Reset rewinds TP0 when idle.

Factory Pause and Reset clear SpindleCW and SpindleCCW without timers or feedback waits. They leave the analog/inverter speed setpoint and LoaderVacuum unchanged. Factory Run is empty: it does not automatically restart the spindle. Ordinary resume does not replay an earlier M3/M4, so verify the required equipment state before continuing.

Engineers may add machine-specific logic to these editable programs. Saved PLC sources remain authoritative across restarts. Failed extension requests are logged. Keep stopping and reset bookkeeping independent of extension completion.

NC Pause and Hold ownership

The application-owned OperatorInterlocks cyclic program combines EmergencySwitch and the assigned NC Pause input into one Controller Hold assignment. OFF Pause prevents new motion admission; ON release does not issue a Run. Do not add a competing Hold writer to custom PLC logic. Only the former factory Hold assignment in saved Background source is migrated; other custom source is retained.

Run/Reset/Pause panel dispatch is sampled every 20 ms on the UI thread; the cyclic Hold gate is separate. These software controls are not a replacement for a safety-rated emergency-stop circuit.
